## 用户需求

在当前空目录中生成一个最轻量的若依风格 Excel 处理示例：一个单页界面，提供选择 Excel 文件与上传按钮，点击后调用处理服务接口；服务端接收文件、预留业务处理 TODO、把处理结果以 Excel 文件流返回供页面下载。除这条主链路外，其余详细业务逻辑由用户自行补充。

## 产品概述

打开一个简洁的后台风格单页，选择本地 Excel 文件并点击上传按钮，页面显示处理中状态；处理完成后浏览器自动下载一份处理后的 Excel 文件；失败时页面给出可读的错误原因。整体只呈现一个功能页面，界面清爽、贴近常见后台管理工具的观感，不过度设计。

## 核心功能

- 单页上传界面：文件选择、上传按钮、处理中/成功/失败状态反馈
- 一次点击完成「上传 → 处理 → 自动下载结果文件」的闭环
- 服务端接收 Excel、留出唯一的业务处理 TODO 扩展点、写出 Excel 文件流
- 基础校验与提示：未选择文件、格式不支持、处理异常
- 简洁的后台分层与命名风格，仅体现结构风格，不引入完整框架能力
- 附带最小运行说明，指明 TODO 位置与访问方式

## 技术栈选型

- Java 8（`maven.compiler.source/target=1.8`，匹配本机 `D:\app\jdk8`）
- Spring Boot 2.5.15（`spring-boot-starter-parent`），仅依赖 `spring-boot-starter-web`
- EasyExcel 3.3.4（`com.alibaba:easyexcel`），无模型读写，JDK8 兼容
- Maven 3.9.16，单模块工程
- 界面：原生 HTML + CSS + JavaScript（FormData + fetch + Blob），零 CDN、零构建工具，作为静态资源由应用直接托管
- 不引入数据库、安全框架、测试框架、Swagger 等，保持最轻量

## 实现思路

- 策略：一次 POST 请求完成「上传 → 读入 → TODO 业务处理 → 写出 → 下载」。页面用 FormData 提交到 `/tool/excel/process`，依据响应是否正常决定把响应体当作文件下载，还是当作 JSON 错误提示。
- 服务链路：`ExcelProcessController` 校验空文件与扩展名 → `IExcelProcessService.process(InputStream)` 用 EasyExcel 无模型 `doReadSync()` 把每行归一为 `List&lt;List&lt;String&gt;&gt;` → 调用 `doBusiness(rows)`（唯一 TODO 扩展点，默认原样返回，保证示例链路可直接跑通）→ 用 `EasyExcel.write(ByteArrayOutputStream).sheet("处理结果").doWrite(rows)` 生成字节 → Controller 以附件流输出 xlsx。
- 关键决策与取舍：
- **不定义业务实体/DTO**：用 `List&lt;List&lt;String&gt;&gt;` 通用行结构，避免预设业务字段，用户补充逻辑时不受数据模型约束。
- **成功返回文件流、失败返回 AjaxResult JSON**（HTTP 4xx/5xx），前端靠 `response.ok` 分支处理，避免「上传接口 + 下载接口」两步式带来的临时文件与状态管理复杂度。
- **若依风格只落在结构**：包前缀 `com.ruoyi`、简化 `AjaxResult`、简化 `BaseController`、`/tool/excel` 路径；不引入若依官方 jar，避免拉取大量无关依赖与配置。
- **内存缓冲**：`ByteArrayOutputStream` 一次写出，换取简单的一请求一响应、不落盘、无临时文件清理负担；示例级数据量下收益大于成本。
- **中文文件名**：使用 Spring 5.3 的 `ContentDisposition.attachment().filename(name, StandardCharsets.UTF_8)` 生成 RFC 5987 编码，避免手工 URLEncoder 导致的乱码。
- 性能与可靠性：读入复杂度 O(行数 × 列数)，内存 O(全部行数)（`doReadSync` 全量载入 + 输出缓冲，大文件时约双倍占用）。缓解：`application.yml` 限制 `max-file-size`/`max-request-size`（如 20MB）；注释中说明大文件可改为 `AnalysisEventListener` 分批读 + `ExcelWriter` 流式写出，本期按 YAGNI 不实现。
- 避免技术债：业务处理收敛到 `doBusiness` 单一方法并打 TODO 注释，用户补充逻辑时无需改动 IO 与响应代码；输入流用 try-with-resources 管理，`doWrite` 由 EasyExcel 自动 `finish()`。

## 实现说明（执行细节）

- EasyExcel 3.3.x 无模型 `doReadSync()` 返回 `List&lt;Map&lt;Integer, Object&gt;&gt;`（列索引为键），实现时按实际泛型转换、按 key 升序拼成行列表，并处理空单元格，避免 NPE 与列错位。
- 本机环境坑：Maven 3.9 + JDK8 默认 resolver transport 下载 jar 会失败（pom 可下载）。README 与验证统一使用 `mvn -Dmaven.resolver.transport=wagon spring-boot:run`，镜像为 `https://maven.aliyun.com/repository/public`。
- 校验与错误：仅做 `isEmpty()` 与 `.xlsx/.xls` 白名单；异常用 try/catch 返回 500 + 简短 msg，不回传堆栈、不打印大 payload（不建全局异常体系）。日志使用 Spring Boot 默认日志，只记录一行异常摘要，不记录文件内容。
- 响应头：`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`、`Cache-Control: no-store`、附件 `Content-Disposition`；前端解析文件名失败时回退默认名 `处理结果.xlsx`。
- 前端：上传期间禁用按钮并提示「处理中…」，成功后创建 a 标签触发下载并 `URL.revokeObjectURL` 释放、`URL.createObjectURL` 及时回收；`response.ok` 为 false 时读取 `AjaxResult.msg` 显示错误。
- 影响范围：工作区确认为空目录，全部为新增文件，无既有代码需兼容；不改动任何默认自动配置，仅通过 `spring.servlet.multipart` 设置大小上限。
- README 写清：接口路径、TODO 位置（`doBusiness`）、构建与运行命令（含 wagon 参数）、访问地址 `http://localhost:8080/index.html`。

## 架构设计

- 分层结构：展示层（static/index.html）→ Web 层（`ExcelProcessController`，继承 `BaseController`）→ 服务层（`IExcelProcessService` / `ExcelProcessServiceImpl`）→ 基础支撑（`AjaxResult`、EasyExcel）。组件关系简单，无需架构图。
- 数据流（单次请求）：选择文件 → FormData POST `/tool/excel/process` → 校验 → 读入 → `doBusiness` TODO → 写出字节 → 附件响应 → fetch 取 Blob → 浏览器下载。
- 异常分支：校验失败或处理异常 → `AjaxResult` JSON + 4xx/5xx → 页面显示错误提示。
- 职责边界：Controller 只做参数校验、响应头与错误映射；Service 只做读入、业务占位、写出；二者通过 `InputStream` 与 `byte[]` 解耦，便于用户后续替换实现。

## 关键代码结构

仅固定服务层扩展点契约，避免实现期对 TODO 位置与数据类型产生歧义。

```java
public interface IExcelProcessService {
    /** 读入 Excel → 业务处理 → 写出 xlsx 字节 */
    byte[] process(InputStream inputStream) throws IOException;

    /** TODO 业务处理扩展点：使用者在此补充详细逻辑，默认原样返回 */
    List&lt;List&lt;String&gt;&gt; doBusiness(List&lt;List&lt;String&gt;&gt; rows);
}
```

```java
@RestController
@RequestMapping("/tool/excel")
public class ExcelProcessController extends BaseController {
    @PostMapping("/process")
    public ResponseEntity&lt;?&gt; process(@RequestParam("file") MultipartFile file);
}
```

## 设计风格

采用简洁的若依后台管理风格：浅灰底 + 白色卡片 + 蓝色主按钮，单页单卡片布局，无外部依赖、无重型动效，仅在按钮悬停与状态切换处加轻微过渡。用户明确要求「最轻量、不要过度设计」，因此以清晰可用为第一目标，保持整洁专业而非堆砌视觉。

## 页面规划（1 个页面）

单页工具页，四个功能块自上而下排列，顶部栏与底部信息栏构成完整框架。

- **顶部导航栏**：左侧蓝色品牌块显示「Excel 处理示例」，右侧浅色小字标注「RuoYi Style · Demo」。固定高度、细底部描边，与若依后台顶栏观感一致。
- **上传主卡片**：居中白色卡片，含标题「上传 Excel 文件」、虚线边框的文件选择区（显示已选文件名）、蓝色主按钮「上传并下载结果」、格式提示「支持 .xlsx / .xls」。按钮带悬停加深与按压反馈。
- **状态反馈区**：卡片内独立浅色条，展示「等待上传 / 处理中… / 处理完成，已开始下载 / 失败原因」。成功用绿色、失败用红色、处理中用蓝色，切换时轻微淡入；上传期间按钮置灰禁用。
- **底部信息栏**：灰色小字列出接口路径 `/tool/excel/process`、业务 TODO 所在位置说明与「详细逻辑由使用者补充」提示，便于开发者定位扩展点。

## 响应式与交互

窄屏时卡片自适应为单列、内边距缩小；上传、下载、错误提示均在同页完成，无跳转。下载通过临时 a 标签触发并及时释放 ObjectURL，避免内存占用。
